# Phase 3.4 — Domain Contract for Phase 4

This document is the conceptual domain model Phase 4 implements.

- **Machine-readable form:** `docs/phase34-model.json`, generated by
  `tools/build-phase34-model.py` from the Phase 3.2 model plus an explicit
  diff.
- **Worked cases:** `docs/phase34-fixtures.json`, sixteen real cases from
  the Phase 3.3 harvest.
- **The reasons:** `docs/PHASE-3.4-DOMAIN-MODEL-REVIEW.md`.

It is not a schema. Storage, id syntax and app access stay Phase 4
decisions (D3, D4, D7). Types are conceptual: `id`, `text`, `enum`,
`ref`, `Validity`, `TemporalBound`.

**Unchanged from Phase 3.2:**

- **Ids** are minted once, opaque, and never derived from or parsed for
  names.
- **Validity** is `{valid_from, valid_to, as_of}`. Each bound is a
  `TemporalBound {kind, axis, value, precision, basis}`.
  - The kinds are EXACT, APPROXIMATE, NO_LATER_THAN, NO_EARLIER_THAN,
    UNKNOWN, OPEN and NOT_APPLICABLE.
  - The axis is CALENDAR or VINTAGE.
  - Every value needs a basis.
- **Provenance** is on every record of the state, observation,
  reconciliation and canonical layers.

## Entities

### Identity

| Entity | Fields | Notes |
|---|---|---|
| **Estate** | id, name_status | a property; names, owners and wines are separate records |
| **Wine** | id, name_status, **type** (WineType), non_vintage | the grand vin is a Wine; `type` is RED, WHITE_DRY, WHITE_SWEET, ROSE, SPARKLING, OTHER or UNKNOWN, and is **independent of rank** |
| **Vintage** | wine, label | composite identity (wine, year or NV) |
| **Source** | id, kind, name, operator, base_urls | a site, publisher or body; never an estate |
| **Party** | id, kind, name, identifiers | owners, groups, institutions; legal identifiers optional |
| **IdentityMap** | namespace, legacy_key, stable_id, candidates, status, provenance | every legacy key, kept for ever |
| **NameRecord** | id, subject, name, kind, **context**, validity, provenance | kinds CURRENT, FORMER, ALIAS, SPELLING_VARIANT, SOURCE_RENDERING, **MARKET_ALIAS**; `context` gives the market or channel |
| **IdentityTransition** | id, kind, from, to, at, certainty, source_term, provenance | RENAMED, SUCCEEDED_BY, SPLIT_FROM, MERGED_INTO, POSSIBLY_SAME, DISTINCT_FROM; required evidence below |

## Relationships

```text
Estate ─ EstateWineRelationship(kind, validity) ─ Wine(type) ─ Vintage
            └─ RankAssertion(tier, scope[, type], claimant, validity)
Estate ─ RankAbsence(tier, scope, claimant, validity)
Wine   ─ WineDescriptor(kind)        Wine ─ ClassificationMembership ─ ClassificationEdition(status) ─ Scheme
Wine   ─ AppellationMembership ─ Appellation(validity)
Estate ─ Ownership ─ Party           Estate ─ EstateLocation          Estate|Wine ─ NameRecord / IdentityTransition
Source ─ SourceEstateRelationship(kind, validity) ─ Estate
Source ─ Placement ─ Locator ;  Placement ─ Artifact(extraction_status) ─ ArtifactDate / ArtifactRelation / DocumentFamily
Artifact ─ Attribution(many) ─ Estate? Wine? Vintage? RankTier?
Artifact ─ Observation(subject, subject_status, lang, asserted_at) ─ Reconciliation ─ CanonicalValue(lang, as_of)
Observation ─ Translation (derived)
```

## Wine model

| Dimension | Where it lives | Values |
|---|---|---|
| Identity | Wine (+ NameRecord, IdentityMap) | name-free id; several names, market aliases, former names |
| Type | Wine.type | RED, WHITE_DRY, WHITE_SWEET, ROSE, SPARKLING, OTHER, UNKNOWN |
| Hierarchy | RankAssertion | tier FIRST, SECOND, THIRD, ABOVE_FIRST, UNRANKED or UNKNOWN; scope ESTATE_RANGE or TYPE_RANGE (plus type); claimant PRODUCER, CLASSIFICATION_BODY, PRESS, TRADE or DATASET |
| Making / selection | WineDescriptor | plot selection, young or old vines … never a rank |
| Estate relationship | EstateWineRelationship.kind | produced by, from estate vineyard, made by group team, sold by, same owner other property, associated |
| Historical state | validity on all of the above; NameRecord FORMER; IdentityTransition | |

A wine nobody ranks has **no** RankAssertion; that is UNKNOWN, and it
never becomes "other". UNRANKED means a claimant said explicitly that no
rank applies.

## Temporal rules

1. Everything in the state layer, NameRecords and IdentityTransitions
   carry a validity. Records are added, never overwritten.
2. **Wine facts use the VINTAGE axis** ("from the 2008 vintage").
   **Institutional facts use the CALENDAR axis** ("juin 1973",
   "8 septembre 2022").
3. **Three dates are never confused:**
   - the document's date: one or more ArtifactDate records, with
     Observation.asserted_at taken from them;
   - the period a fact holds: the validity of the state record;
   - the retrieval date: on the Placement.
4. "Today", "now" and "currently" make a statement **as of asserted_at**,
   not timeless.
5. A bound never claims more precision than its source:
   - "pendant plus de 30 ans" is UNKNOWN;
   - "from the 2008 vintage" is EXACT VINTAGE 2008, ending its
     predecessor at NO_LATER_THAN 2007.

## Evidence model

```text
Artifact (bytes) → Placement (where, when) → Observation (what it says, as said)
→ Reconciliation (all candidates, a named rule) → CanonicalValue (projection, with provenance)
```

**No first-writer-wins.** Language versions and revisions are linked as
candidates; they are never merged.

## Source model

```text
Source (site, group, body) → Placement → Artifact
Source → SourceEstateRelationship → Estate
```

A source is never an estate's identity.

## Attribution

- Every judgement of what a document concerns is an Attribution.
- An artifact can have many.
- Method and status are always recorded.
- Crawl context is CRAWL_CONTEXT, the weakest method.
- A null wine is "not established", never the grand vin.

## Language

- An Observation keeps its source language (`lang`) and raw wording.
- A CanonicalValue of text type carries its own `lang`.
- A translation is a Translation, derived, never an Observation.
- Parallel documents are linked by a candidate ArtifactRelation
  LANGUAGE_VERSION_OF and reconciled like any other candidates.

## Quality

QualityFinding attaches to any record and changes nothing:

- **conflict:** CONFLICT;
- **missingness:** MISSING, raised only against a sourced expectation;
- **extraction and OCR:** EXTRACTION_FAILURE;
- **access:** SOURCE_FAILURE;
- **identity:** IDENTITY_UNCERTAIN;
- **scope:** SCOPE_DISCREPANCY;
- plus the other kinds defined in Phase 3.2.

## Discovery-only data

Information of taxonomy classes B to F stays as Observations, Artifacts
and DocumentFamilies. Phase 4 may not promote it to canonical fields
without a later review:

- winemaking and viticulture narratives;
- tasting text per source;
- press scores;
- commercial and tourism data;
- legal notices;
- history narrative;
- unclassified labels.

The canonical fields of class A are listed in the review, §10.

## Required evidence for identity changes

| Transition | Evidence required |
|---|---|
| RENAMED (one Wine, new name) | the source names one wine as the continuing subject under a new name ("La Parde … se voit renommer"; "a new identity was given to the second wine") |
| SUCCEEDED_BY (two Wines) | the source presents the new wine as replacing a discontinued one, without continuity |
| SPLIT_FROM / MERGED_INTO | dated statements for both sides |
| POSSIBLY_SAME | the same name with no statement either way |
| none | no evidence: a new wine with no transition record |

## Migration boundary

Phase 4 **may**:

- implement this contract;
- run the Phase 3.2 migration stages M0–M9, with RankAssertion in place
  of RoleAssignment;
- ingest the Phase 3.3 harvest into Artifact, Placement, Observation and
  Attribution;
- project the class A canonical fields;
- decide D3, D4 and D7.

Phase 4 **must not**:

- promote class B–F information to canonical fields;
- apply Echo, Terrasses or Murets except as recorded domain decisions in
  this model;
- resolve unresolved identities or ranks by inference;
- rewrite v1–v5 evidence or the Phase 3.3 discovery data.
