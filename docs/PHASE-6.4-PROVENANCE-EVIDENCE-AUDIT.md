# Phase 6.4 — Provenance and evidence UX audit

Gate: **SAFE — PHASE 6.4 PROVENANCE/EVIDENCE AUDIT COMPLETE — READY FOR IMPLEMENTATION**

Audit only. This document is the single output. No model, canonical, evidence, artifact, discovery,
scraper, generated-data, UI, translation, CSS, cache, URL, provenance or identity change was made.
No provenance was repaired, no source added, and no value's correctness was judged.

## 1. Executive summary

The audit keeps four things apart throughout:

1. what the model says;
2. what evidence supports it;
3. how the evidence became the model value;
4. what remains uncertain.

**Coverage.** The Phase 6.1 inventory reproduces exactly, with no differences:

| Figures | Count |
|---|---:|
| Linked to their own source | 2,142 |
| Own file named, no address recorded | 304 |
| "Source unclear" | 96 |
| No established source | 2,149 |
| **Total** | **4,691** |

The document behind every linked or file-only figure is held locally, and its bytes are proven.
For all 8,278 field-sourced observations, sha1 is joined to sha256.

**What the model does not hold.** The step from a document to a figure is the weak link:

- no passage, location, extraction method or confidence is recorded for any legacy figure;
- every one is `extraction.method = LEGACY`;
- no publication, revision or retrieval date is held for any artifact (`artifact-dates`: 0 rows; every
  placement's `observed` bound is UNKNOWN);
- evidence links tie a document to an estate or wine, never to a field or value. "The sheet says X,
  the model says Y" cannot be expressed.

**What the app hides that the model already has:**

- the document type (web page, PDF, group report);
- that a linked "source" for 2,060 figure entries is a web page whose text we kept, not a document;
- the file name and the ambiguity count, which sit in a `title` tooltip that touch and keyboard users
  cannot reach;
- that four linked pages are each cited for several estates.

**Trust-critical findings (P1).** There are five:

- **F1:** the Compare tab's single record-level "Sheet" link sits under figures read from other
  documents, and merged cells drop per-vintage sources.
- **F2:** the website labels say "confirmed by reading it" and "checked by hand" for tags the model
  records as LEGACY_UNSOURCED.
- **F3:** sparse estates are introduced as "A verified name and rank", which are unsourced dataset
  transcriptions.
- **F4:** an unmapped website tag falls back to "from Wikidata". This affects one estate (Suau, tag
  `handx`).
- **F5:** one linked sheet, *FT-Ch-Braude-Fellonneau-2015-GB.pdf*, is cited for the 1999 oak and yield
  of two different estates (Braude, Mongravey), and nothing on screen signals the mismatch.

**Recommendation: B.** A focused provenance UX implementation is possible from data the model already
holds (section 19). Passages, dates, extraction method, confidence, and evidence-against-value
conflicts need the model and evidence layer extended. That is a separate, later decision; it does not
block B.

Explicit means recorded as a fact; inferred means derived by a rule.

- between the model and the generated data, where artifact identity, hash, document type and
  provenance kind are dropped;
- between the evidence and the value, where no passage, location or method was ever recorded.

## 7. Exact-source fidelity

Measured over the 3,709 linked field entries. The model is not changed and correctness is not judged.

| Question | Answer |
|---|---|
| **A. Is this the actual artifact?** | **1,649 entries (1,544 + 105): yes, as far as recorded.** The URL is the address the PDF was fetched from (manifest claim). **2,060 entries: no.** The URL is a web page; the artifact is our text extraction of it. The page is the source, but not as it is now. |
| **B. Can it be matched to the harvested artifact?** | **In the model, yes, for all 8,278 field-sourced observations:** provenance → artifact → sha1 claim joined to a proven sha256, `bytes_available`. **In the generated data and the UI, no:** `figure-sources.js` carries only the file name and URL. |
| **C. Can the exact version be identified?** | **By bytes, in the model, yes.** By date or version label, no: there are no dates and no version relations. Online, the URL may now serve other bytes, and nothing records when it was fetched. |
| **D. Can the user tell "this page is the source" from "the page where we found the document"?** | **No.** Every link reads "source". The 2,060 page-text entries look identical to the 1,649 PDF entries. The model records no referring page for a legacy figure: the URL is always the fetched address, never a landing page that linked to it. The distinction cannot arise, and the page-against-document distinction is not shown. |

## 14. Compare-tab Sheet limitation

Reproduced in headless Chrome: Compare, one estate, Cantemerle, vintages 2019 and 2020.

| Row | Cells | Source marks |
|---|---|---|
| Blend | 2019: 68/23/5/4; 2020: 58/29/7/6 | none |
| In barrel | one merged cell, "12 months" | none |
| New oak | one merged cell, "40%" | none |
| Sheet | 2019: "the 2019 sheet" → *FT-Cantemerle-2019-EN.pdf*; 2020: "—" | — |

**The finding (F1).** Compare shows no per-figure source. Its one record-level link (`srcLine` without a
field, `'grand'` only) is the only provenance in the table:

- Cantemerle 2019's "12 months" was read from the **FR** sheet, but the table's sheet link goes to
  the **EN** sheet.
- When two vintages share a value, `cmpRow` merges the cells. The per-vintage sources, which can
  differ, then have nowhere to go.
- Where a record has file-only figure sources but no record URL, as Cantemerle 2020 does, the Sheet
  cell shows "—". It reads as "no sheet" although the figures have sources on file.
- Second wines get no Sheet link (`'grand'` is hard-coded).

The drawer says "each figure above cites its own source"; Compare has no equivalent. Phase 6.1's fix
does not reach this tab.

At 390 px wide (device scale 2, touch emulation):

## 19. Recommended next phase

**B: a focused provenance UX implementation.** It is bounded to data the model already holds, plus
wording.

**In scope:**

1. **Compare (F1, F14):** per-figure source marks in Compare, using `figSrc` as the drawer does. Do
   not merge cells whose sources differ. Relabel or remove the record-level Sheet row so it cannot
   read as the figures' source; cover second wines.
2. **Trust wording (F2–F4):**
   - website labels that describe how the address was recorded, not that it was verified;
   - "verified" removed from the sparse-estate notice;
   - an honest fallback for an unmapped tag ("source not recorded"), not "Wikidata".
3. **Level 2 summary (F6–F9, F11):** a tappable, focusable disclosure in place of `title`-only
   detail, showing:
   - the file name;
   - the document kind, from the model's assessment or extension (PDF / web page, text kept / group
     report);
   - "kept on file, not published by this app" for file-only sources;
   - the candidate count for ambiguous ones;
   - "also cited for N other estates" where a URL is shared;
   - for a blank, which section 9 category applies.

   This needs `build-app-data.py` to generate the document kind and the blank category, an addition
   to generated data, not to the model.
4. **F5 and F10:** show, do not fix:
