## 2. The representation chosen

The evidence store already versions decisions:
- one append-only file per decider version;
- `evidence_store.latest_by_context()` reads, for each question, the answer of the highest version that asked it.

M3.6B uses that, and adds the least it needs:
- **Decider version 6.** Its reader fingerprint is that of the rules that decide (`tools/m35_rubric.py` + `tools/web_evidence.py`): `6f68a0af15d3`. The store's rule holds: a version is one reader.
- **A mapping** is a v6 ACCEPTED row (kind `web_page_review`) for the page's estate, wine and vintage. It reads the held bytes under `sources/discovery/` (path and SHA-256), and its evidence is the page's main heading and vintage source.
- **A correction** is a v6 REFUSED row asking exactly the question the historical v5 row asked: the same artifact and context, so its row key differs only in `v`. `latest_by_context()` now reads the correction; the v5 row is untouched. The relation is explicit:
  - `supersedes` names the v5 row (row key, version, decision, code);
  - `code` is the precise M3.6A category (WRONG_ESTATE, WRONG_WINE), not a broad CORRECTED state;
  - `replacement` names the accepted decision for the document's own target, and its model attribution where one exists;
  - `document_is` keeps what the document is, even when the model has no such wine.
- **A historical flag** is an audit record (`data/audit/m3.6b-historical-flags.jsonl`), not a decision. The v5 acceptance stays the latest answer. The model's findings could hold it, but a new finding changes the gap register's identity counts, which M3.6B may not touch.
- **Git provenance.** Every v6 row carries the git state it was written in (the store requires it from v4 on).
  - The runs were made with the M3.6B code not yet committed and the three retained blocked-run files present, so the rows say `dirty`. Their `status_hash` names that exact state: the store's provenance mechanism, not a gap.
  - `--check` recomputes every row and compares all of it but that stamp, which must name a commit in HEAD's history.
